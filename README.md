# Lebon Toy — ระบบจัดการสต็อก

ระบบคลังสินค้าแบบร้านเดียว ใช้ Supabase เท่านั้น: สินค้า รับเข้า เบิกออก ตรวจนับ และประวัติความเคลื่อนไหว ไม่มีงานขาย รับเงิน หรือรายงานกำไร แต่เก็บราคาขายเป็นข้อมูลอ้างอิงของสินค้า

## ความสามารถ
หน้าจอใช้โทนและผังแบบ Lebon Toy เดิม: หัวเว็บสีเข้ม เมนูแนวนอน การ์ดภาพรวม และเมนูล่างบนมือถือ
- สินค้า หมวดหมู่ หน่วยนับ รูปภาพ ราคาขายอ้างอิง และแจ้งเตือนใกล้หมด
- รับเข้า / เบิกออกครั้งละ 1–100 รายการ พร้อมเหตุผล ปลายทาง และรูปเอกสาร
- ต้นทุนเฉลี่ยถ่วงน้ำหนัก รวมของรับเข้าฟรี และมูลค่าสต็อกสำหรับ Admin
- ตรวจนับโดยตรวจว่ายอดตั้งต้นยังไม่เปลี่ยน; ย้อนเอกสารใหม่โดยคงประวัติเดิม
- เครื่องสแกนคีย์บอร์ดและกล้อง; ส่งออก CSV ภาษาไทย; ประวัติแบ่งหน้าตามเวลาไทย
- คิวออฟไลน์แยกตามบัญชี ส่งซ้ำด้วยรหัสเดิม และยกเลิกคิวที่ฐานข้อมูลเพื่อป้องกันคำขอล่าช้า
- จัดการผู้ใช้ ระงับบัญชี เปลี่ยนรหัสผ่าน และประวัติการแก้ไข

## บัญชีเดิม
คงชื่อผู้ใช้ `admin` และรหัสผ่านเดิม รวมถึงบัญชีเดิมอื่น ไม่ต้องใช้อีเมล
ฐานข้อมูลออก session สุ่ม อายุ 8 ชั่วโมง และตรวจบัญชี/สิทธิ์ทุกคำขอ
ไม่มีรหัสผ่านเริ่มต้นใหม่ และไม่เชื่อ role/operator ที่ส่งจากเบราว์เซอร์
Staff รับเข้าโดยใช้ต้นทุนเดิมได้; ระบุต้นทุนใหม่และตรวจนับต้องเป็น Admin

## พัฒนา
ใช้ Node.js 24 และ pnpm ตาม package.json

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm dev
```

ทดสอบหน้าจอ: `pnpm exec playwright install chromium` แล้ว `pnpm test:browser`
ทดสอบใช้ข้อมูลจำลอง ไม่ส่งรายการเข้าร้านจริง

## เผยแพร่
อ่าน [ขั้นตอนเปลี่ยนระบบ](docs/CUTOVER.md) ก่อนใช้ migration ใน supabase/migrations/
ต้องสำรองและทดลองกู้คืนก่อน ปิดการทำรายการเดิมระหว่างเปลี่ยนระบบ
เว็บใหม่และ migration ต้องขึ้นพร้อมกัน เพราะ API รุ่นเก่าจะถูกปิด
Vercel: build `pnpm build`, output `dist` หรือเผยแพร่เฉพาะ dist บน HTTPS
ห้ามใส่ service-role key หรือรหัสผ่านฐานข้อมูลใน src/config.js

## ข้อมูลเดิมและออฟไลน์
- สินค้าและประวัติเดิมไม่ถูกลบ คอลัมน์งานขายเดิมคงไว้เพื่อรักษาประวัติ แต่ API และหน้าเว็บใหม่ไม่ใช้
- ไม่มีการเชื่อม Google Sheets / Apps Script และไม่สลับไปเขียนฐานอื่นเมื่อเครือข่ายมีปัญหา
- คิวเดิมไม่ส่งอัตโนมัติ ต้องกระทบยอดก่อนเปลี่ยนรุ่น
- ขณะออฟไลน์ บัญชีที่เปิดใช้งานอยู่สร้างรายการรอส่งได้ ยอดแสดงเป็นยอดยืนยันล่าสุด
- ต้องออนไลน์เพื่อเข้าสู่ระบบ/ตรวจ session หลังเปิดเว็บใหม่ และเพื่อปรับยอดตรวจนับ
- คิวคงอยู่เมื่อปิดเบราว์เซอร์ แต่การล้างข้อมูลไซต์อาจทำให้คิวสูญหาย
- กล้องต้องใช้ HTTPS และได้รับอนุญาตจากอุปกรณ์
